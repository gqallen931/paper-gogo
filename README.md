# Paper-gogo v6.0

Paper-gogo 是一个“审稿人倒推、证据优先”的论文研究与修改工作流。v6以v5完整18阶段正文为基础，不删除原有实验、写作、投稿和返修流程，只增加证据门禁、写作升级与真实本地技能路由。

## 核心变化

- 默认先建档，不再收到论文后直接重写全文。
- 用“现象—机制—条件”提炼研究问题。
- 用“真实失败—领域机制—方法设计—判别实验”判断交叉AI创新。
- 将问题分为表达、论证和证据三类，防止用文字掩盖实验缺口。
- 为主张标记 SUPPORTED、INFERRED、VERIFY、MISSING 四种证据状态。
- 加入三审稿人诊断、作者/编辑意见分流和100分诊断量表。
- 为Phase 0-17分别指定一个主技能、条件辅助技能、入口门禁、产出和失败回退。
- 文献采用“核心集全文深读 + 扩展集分层筛选”，不再用固定篇数替代覆盖度。
- 每张正文图生成 figure brief；整篇论文最多一份独立 Graphical Abstract。
- Phase 5/9 的概念框架图与 Phase 13 的终稿框架图使用独立状态，避免流程重复污染。
- 将“去AI率”改为“学术语言与作者声音”，不以检测器规避为目标。
- 将“录用概率”改为定性风险和决策模拟，避免伪精确判断。

## 快速使用

启动完整工作流：

```text
/paper-gogo
```

上传论文后直接发出命令：

```text
/建立档案
/审稿人诊断
/检查创新
/领域偏置
/证据审计
/修改引言
/修改实验
/设计消融
/分析难例
/投稿前检查
/回复审稿人
```

如果没有指定命令，默认只执行 `/建立档案`。

## 推荐路线

已有论文修改：

```text
/建立档案 → /审稿人诊断 → /检查创新 → /证据审计
→ 按章节修改 → /投稿前检查
```

新研究项目：

```text
Phase 0 建档 → Phase 1 问题准入 → Phase 2-3 文献与证据
→ Phase 4 创新审查 → Phase 5 实验协议 → Phase 6-8 实现与证据审计
→ Phase 9-15 写作与整合 → Phase 16-17 投稿与返修
```

低算力或行业数据项目：

```text
/分析难例 → 找到多模型共性失败 → /提炼问题 → /领域偏置
→ 公开基准 + 真实场景双验证 → /证据审计
```

## 质量门禁

| Gate | 目标 |
|---|---|
| G0 | 期刊范围、材料和伦理准入 |
| G1 | 研究问题重要且可回答 |
| G2 | 创新由领域机制和文献支持 |
| G3 | 研究设计能检验核心主张 |
| G4 | 实验证据支撑结论 |
| G5 | 全文论证一致且可复现 |
| G6 | 投稿文件、引用和披露完整 |

门禁结果为 `PASS`、`PASS WITH CONDITIONS` 或 `FAIL`。失败门禁必须给出修复路径，不能靠润色覆盖。

## 安装

将整个 `Paper-gogo` 目录复制到所用工具的 skills 目录，并确保入口文件仍为 `SKILL.md`。外部ZIP压缩包不视为已安装技能；只有解压后存在可读取的 `SKILL.md`，工作流才可以调用它。

本包已公开发布在 <https://github.com/gqallen931/paper-gogo>（Public）。发布前的凭据、身份、稿件数据、许可证与编码检查记录在 `PUBLIC_REPO_SETUP.md`；新增内容前须重跑这些检查。
